# Шпаргалка по панелям: слой OS

Формат: на что смотреть → что допустимо → как чинить. Пороги — для выделенного
хоста БД, про **устойчивые** значения (секундные пики — норма). В демо
(Docker Desktop) метрики видят всю VM — фоновые единицы процентов нормальны.

## Pressure Stall (PSI)

- Устойчивые плато, не пики; memory — строже всех. Рост PSI при неизменной
  своей нагрузке (QPS/IOPS/CPU% прежние) = виновато не-Postgres.
- cpu/io < 5%; memory ≈ 0 (уже 1–2% = идёт reclaim).
- cpu → сверить CPU% и steal; io → латентность vs IOPS ниже; memory → swap и
  OOM kills, реагировать сразу. Если нагрузка не менялась — эскалация в
  инфраструктуру (сосед/гипервизор/троттлинг), в базе чинить нечего.

## CPU Usage

- Доли user/system, линия steal, iowait.
- Запас до потолка; steal < 2–5%; iowait — единицы %.
- user↑ → «Top: CPU по запросам» (kcache, слой 4); system↑ → коннект-шторм
  (нужен пулер) или выключенные huge pages; steal↑ → гипервизор отдаёт ядра
  соседям — менять хост/тариф.

## Load Average

- load1 против линии cores.
- load < числа ядер.
- load > ядер при высоком CPU% → см. CPU-панель; при НИЗКОМ CPU% → процессы
  стоят в D-state за диском → дисковые панели.

## Memory Available

- Тренд вниз, не мгновенное значение.
- Устойчиво > 15–20%.
- Меньше коннектов × work_mem (пулер), пересмотреть shared_buffers,
  добавить RAM. Сверить с PSI memory: available может врать, PSI — нет.

## Disk Latency

- Каждое устройство отдельно (том WAL — критичный).
- SSD/NVMe: read/write единицы мс; > 10–20 мс — плохо.
- Рост при ПРЕЖНИХ IOPS → диск деградировал / сосед / троттлинг облака —
  инфраструктура. Рост ВМЕСТЕ с IOPS → своя нагрузка → pg_stat_io
  «кто пишет/читает» (слой 2) → топы запросов.

## Disk IOPS

- Близость к паспортному лимиту тома; пилообразность в ритме чекпоинтов.
- < ~70% лимита тома.
- Найти потребителя (pg_stat_io, топы по чтению/WAL); растянуть чекпоинты
  (max_wal_size↑); поднять IOPS: класс/размер тома, лимит инстанса, NVMe,
  WAL на отдельный диск.

## Disk Space Free

- Тренд худшего тома: WAL/temp-спиллы съедают место за минуты, не дни.
- > 20–25%.
- Маршрут «место кончается»: размер pg_wal (мёртвый слот? висящий архиватор?)
  → temp-файлы (work_mem/кривой запрос) → bloat (pg_repack).

## Disk Queue Depth

- Рост — он опережает рост латентности.
- SATA/SAS SSD: единицы; NVMe: десятки.
- Как io-PSI/латентность: найти кто нагрузил и размазать (чекпоинты, vacuum
  cost limit) либо диск быстрее.

## Swap I/O

- Устойчивый swap-OUT (swap-in — лишь чтение обратно ранее выселенного).
- 0; редкие всплески терпимы.
- Памяти не хватает: см. «Память: доступно» и PSI memory; проверить
  vm.swappiness (1–10), убрать лишние процессы с хоста.

## Swap / Dirty Memory

- Рост dirty при медленном диске (надвигающийся writeback-шторм); занятый
  swap сам не обнуляется — активность смотреть по Swap I/O.
- dirty заметно меньше vm.dirty_bytes; writeback эпизодический.
- Диск не успевает за записью: vm.dirty_background_bytes/dirty_bytes вниз
  (раньше начинать фоновый сброс), быстрее диск, растянуть чекпоинты.

## OOM Kills

- Любое значение > 0.
- Строго 0. OOM-kill бэкенда = crash-recovery ВСЕГО инстанса.
- Жертву искать в dmesg. Защита: vm.overcommit_memory=2 (+ratio) либо
  OOMScoreAdjust=-1000 у postmaster; снизить коннекты × work_mem.

## Network Traffic

- Приближение к полосе NIC; всплески = репликация/бэкапы.
- < ~70% полосы NIC.
- Развести бэкапы/репликацию по времени или интерфейсу; быстрее NIC.

## Network Errors

- Любой устойчивый ненулевой rate.
- 0.
- Драйвер/кабель/MTU/ring buffers (ethtool -g) — инфраструктура, эскалировать.
  Для БД это рваные коннекты и лаг репликации без видимой причины.

## Hardware & Kernel Settings

- Расхождение значения с рекомендацией в имени строки. Отсутствующая строка =
  «не собирается» (нет include-флага / sysctl в ядре), а не «всё хорошо».
- Соответствие рекомендациям: overcommit_memory=2 (или 0 + OOMScoreAdjust),
  swappiness 1–10, dirty ~256MB/1GB, nr_hugepages ≥
  shared_memory_size_in_huge_pages (таблица настроек PG, слой 2).
- sysctl -w + зафиксировать в /etc/sysctl.d. Менять осознанно и не в инцидент;
  hugepages пересчитывать при каждом изменении shared_buffers.

## Manual Checks (not exported)

- Текстовая памятка: THP, I/O scheduler, readahead, governor, clocksource,
  noatime, лимиты systemd-юнита.
- THP=never, scheduler none (NVMe) / mq-deadline (SSD), governor=performance.
- Проверять руками при вводе хоста в строй; на проде — снимать
  textfile-коллектором node_exporter.
